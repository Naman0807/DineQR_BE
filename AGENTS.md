# DineQR Backend — Agent Guide

## Quick start

```bash
source venv/bin/activate
uvicorn app.main:app --reload          # dev server
alembic upgrade head                   # run migrations
```

## Architecture

- FastAPI async, SQLAlchemy 2.0 async (asyncpg), Pydantic v2, JWT (PyJWT + bcrypt)
- Multi-tenant: every User belongs to a Restaurant; admin endpoints scope by `current_user.restaurant_id`
- Two API layers: **admin** routes (JWT `Bearer` via `get_current_admin_user`) and **public** routes (no auth, keyed by `restaurant_slug`)
- DB schema: `Restaurant` → `User`/`Table`/`MenuCategory` → `MenuItem`/`OrderSession` → `Order`/`OrderItem`/`Bill`
- WebSocket manager lives in `app.state.manager` (initialized during lifespan). Endpoints: `/ws/admin` (JWT required, `ADMIN` role) and `/ws/table/{table_id}` (token optional)
- Superadmin user auto-seeded on startup from `SUPERADMIN_USERNAME`/`SUPERADMIN_PASSWORD` env vars
- Registration creates restaurant in `PENDING` status; superadmin must approve via `PATCH /api/superadmin/restaurants/{id}/status`

## Critical gotchas

- **Duplicate enums**: `app/models/models.py` and `app/schemas/schemas.py` define the same enum classes independently. Always update both in sync.
- **Alembic sync URL**: `alembic.ini` uses a **sync** postgres URL (`postgresql://` without `+asyncpg`). Do NOT change to the async driver string — Alembic needs sync.
- **Auto-create tables**: `init_db()` calls `Base.metadata.create_all` on startup. For dev, you can skip migrations; for prod, use `alembic upgrade head`.
- **No tests, no linter, no formatter config in repo** — verify changes manually.
- **Python 3.11.9** specifically (per `todolist.md`).
- **CORS defaults** to `http://localhost:3000,http://localhost:5173` (React/Vite dev servers).

## Common patterns

- Public endpoints: `GET /api/{resource}/public/{restaurant_slug}/...`
- Admin endpoints: `GET /api/{resource}/...` → `Depends(get_current_admin_user)`
- QR token format: `res_tbl_<12 hex chars>` (generated by `secrets.token_hex(6)`)
- JWT: 24h expiry, HS256, claims `{"sub": user_id, "role": role_value}`
- `TableResponse` includes optional `restaurant_slug` from a join after query — do not rely on `relationship` for it.

## Branching Rules (MANDATORY)

Read `BRANCHING.md` at the repo root and follow it. Summary:

1. `main` = production. NEVER commit directly.
2. `dev` = shared integration base. ALL new work branches off `dev`. ALL completed features merge back into `dev`.
3. Feature branches: `feature/<short-description>`, one per task.
4. NEVER work directly on `dev` or `main` — always on a feature branch.
5. Before starting ANY task: `git checkout dev` → `git pull origin dev` → create feature branch.
6. When a feature is complete & tested: merge feature → `dev`, push `dev`.
7. Definition of Done must pass before merging into `dev` (see BRANCHING.md).
8. NEVER force-push to `dev` or `main`.
